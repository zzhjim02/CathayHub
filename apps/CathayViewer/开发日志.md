## v0.1.6（2026-09-24 · batch26：出处定位 + 文档句柄泄漏）

### 用户提的两个问题
1. 「打开出处」在文件不在当前文件列表时没反应 → 要求记录绝对路径。
2. 连点几次「打开出处」越来越卡 → 怀疑每次都真的重开一次 PDF。

### 排查结论
- **绝对路径其实一直在记**（`_pd_path`，含空格/中文都不丢，实测读回一致），
  所以问题不是"没记"，而是**路径失效后没有任何回捞手段**：旧逻辑只会在
  `self.db` 里 `like_stem` 前缀匹配，库里没有就返回空，然后往状态栏丢一句话
  ——用户看到的就完全是"点了没反应"。
- **卡顿是真的**：`_open_path` 每调用一次就 `fitz.open` 一本新 Document 覆盖
  `self.pd`，**旧 Document 从不 close**（7 处赋值全是这样）；`PdfView.clear()`
  也只做 `self.doc = None` 不关文档。于是句柄 + 内存一路堆积，而且每次都要
  重建 n 个 `PdfPageItem`、重算 `_scan_page_sizes`。

### 改动
- `viewer_tools.py`
  - `meta_line(..., extra=)` / `parse_meta()`：元信息新增 `fn / sz / np`
    （文件名、字节数、页数）——路径会失效，这三项跟着文件本身走。
  - `file_probe(path)` 自动取指纹；`add_excerpt` / `add_snapshot` 内部调用，
    可选 `npages=` 让已经打开的书省一次 `fitz.open`。
  - 新增位置修正表 `filepaths.json`（`load_path_map` / `save_path_map` /
    `remember_path`）：`remember_path` 会连带登记归一化路径键 **和文件名键**
    （仅新旧同名时），一次指认同书全部获益。
- `gui.py`
  - `_find_file_by_hint(hint, fn, size, npages)` 重写为七级回捞：
    绝对路径 → **别名表** → 索引库文件名精确 → **原路径尾部目录逐级比对** →
    书名主干前缀 → 备用库 → 已登记 roots 扫描（限量 20000 项 / 3 秒，不卡 UI）。
  - `_same_size_npages()`：候选与记录的字节数/页数对得上才认（老记录没指纹则不否决）。
  - `_ask_missing_source()`：找不到时**弹窗说明**并提供「手动指定…」，选完记住并立刻打开。
  - `_set_pdf(d, path)` / `_release_pdf_doc(doc)`：换书前先把仍在引用旧文档的视图
    `clear()`，再 `doc.close()`；7 处赋值全改成 `_set_pdf`。
  - `_same_pdf_already(path)` + `_open_path` 幂等快路径：目标书已开着就只切视图，
    不重新解析、不重建页控件；另加 `_opening` 防重入锁。
- 验证 `_verify_b26.py`（offscreen）**27/27**；回归 tools 自检、rhyme 自检、
  selftest/selftest2、b23（53）/ b24（36）/ b25（15）全 OK。

## v0.1.5 修订（2026-09-24 · 启动态：不弹空阅读器 / 列表不被拉宽）

用户反馈「直接打开软件、没开 PDF 时，阅读器不需要自动弹出来，文件浏览器一开始也不需要那么宽」。查下来 `_collapse_reader_if_idle()` 其实**跑了**（`_reader_collapsed=True`、`reader_panel.isHidden()=True`），但收起之后**左栏独占整个窗口**：实测 1000 宽的窗口下文件浏览器被拉成 982 宽——用户看到的「那么宽」和「右边一大片空白」都是这个。

- `_collapse_reader_if_idle()`：加幂等判断（已收起直接返回）；未布局好（`sizes()[1] <= 0`）时保留下一次重试的机会。
- 新增 `_shrink_to_list()`：空闲态把窗口收成「列表够用」的宽度 —— `min(max(560, 上次左栏宽 + 300), 760)`，并夹进屏幕可用区；同时把原窗口尺寸记到 `_idle_full_geom`。
- `_expand_reader()`：开文件时**先还原窗口宽度**（`max(1000, 原宽)`，受屏幕可用区限制），再放下阅读区并按 `_split_sizes_idle` 分配左右。
- `resizeEvent` 里记 `_user_resized_idle`：空闲态若被用户手动拉过宽度，开书时就不再强行改回去（只展开阅读区）。
- `main()` 在 `win.show()` 之后、首帧之前先调一次，避免「先画宽、再变窄」闪一下；并保留 `QTimer` 重试（0 / 每 120ms，最多 13 次）兜底。
- 验证：`_verify_b25.py`（offscreen，**15 项全 OK**）——空闲态阅读区隐藏且宽度 0、窗口 640 / 列表 622、重入不越收越窄、开文件后自动展开且窗口 640→760（受 offscreen 屏幕 800 宽限制，真机会还原到 1000+）、用户手拉宽度被尊重。回归：`selftest` / `selftest2` OK，`_verify_b23` 53 项、`_verify_b24` 36 项全 OK。

## 当前状态（2026-09-27 · batch30：命中词两行并成一行）

用户原话："为什么有两行，一行是「本书命中：XXX」，一行是「命中词：xxx」"。

- **根因是历史叠床架屋**：batch28 加了**独立的命中词导航条**（标签「命中词」+ 下拉 + 上一处/下一处/下一个词 + 计数），batch29 又在**文内查找栏**里加了一遍同一批词（「本书命中：…」+ 命中词下拉）。两批需求各加一个，同一件事上下两行各说一遍。
- **改法**：导航条这一行**从布局里撤掉**（控件与 `viewer_hits` 那套逻辑都留着，属性、自检、坏清单处理都不受影响，只是不再摆出来），它的活搬到查找栏那一行：
  - 查找栏现在长这样：`本书命中：吴佩孚(3页/27处)、子玉(1页/3处) ｜ [所有关键词 ▾] ｜ 下一个词 ▸ ｜ 查找 [____] 上一个 下一个 第 N / M 处 ✕`
  - **下拉第 0 项是「所有关键词」且默认选中**：每个词各扫一遍，**按出现先后混排成一条序列**（先页码、同页再按页内偏移），"上一个 / 下一个"顺着这条序列一处一处走 —— 而不是一个词看完再跳回开头。
  - 挑某一个词时只在这个词的命中里走；「下一个词」在几个词之间**循环**。
  - **「所有关键词」模式下「下一个词」置灰**（不需要换词），高亮是**所有词**；单词模式只高亮那一个词。
  - 快捷键照旧：`Alt+←` / `Alt+→` 换词，`Alt+↓` 下一处。
- **高亮终于支持多词**：`set_highlight()` 现在收得下字符串**或**一串词，`_page_hl()` 逐个词 `search_for` 后合并矩形。
- **顺手修掉的两个真 BUG**（都是探针抓出来的，不是我读出来的）：
  1. `_find_jump()` 末尾没有刷新计数标签 → 批量检索完还停在「第 0 / N 处」。
  2. 更要命的一条：跳转时 `set_highlight(self._hl_kw)`，而多词模式下 `_hl_kw` 是空的 —— 等于**一跳就把"所有关键词"的高亮一笔勾掉**。改成多词模式下拿 `_hl_multi` 去设。
- 为让同页多处也能排准，`_scan_pdf()` 的命中现在**记下页内偏移 `off`**（原来只有页码）。
- 自检：新增 **`_probe_b30.py` 31/31**；`_probe_hits` 18/18、`_probe_hitbar` 20/20（已改为验"导航条不再出现 + 旧函数仍可用"）、`_probe_batch29` 全过、`gui.py --selftest` OK。
- 备份：`_bak_20260927\gui.py`。
